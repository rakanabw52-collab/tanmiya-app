# استعادة الحساب — الإصدار 1148

- خيار «نسيت البريد أو كلمة المرور؟» متاح من شاشة الرمز وشاشة تفعيل الحساب.
- يطلب بريد الحساب ويرسل رابط استعادة عبر Supabase Auth دون معرفة كلمة المرور القديمة.
- يفتح حدث PASSWORD_RECOVERY شاشة كلمة مرور جديدة مع التأكيد؛ لا يفتح بيانات التطبيق.
- بعد حفظ كلمة المرور تُغلق جلسة الاستعادة، ويُملأ البريد في شاشة التفعيل. يسجل المستخدم الدخول بكلمة المرور الجديدة ويختار رمز الأربع أرقام. يظل شرط تسجيل الدخول الحديث بكلمة المرور على خادم PIN قائمًا.
- نسيان البريد نفسه أو فقدان الوصول إليه يحتاج تحققًا من الهوية ومساعدة مالك النظام؛ لا تكشف الواجهة الحسابات ولا تنشئ حسابًا بديلًا.

## متطلبات النشر

في Supabase > Authentication > URL Configuration، أضف عنوان التطبيق الفعلي إلى Redirect URLs (الواجهة تستخدم origin + pathname دون استعلامات أو رموز جلسة). اضبط Site URL على عنوان التطبيق أيضًا. افتح التطبيق من العنوان المسموح عند طلب الاستعادة. يجب إعداد SMTP بحيث يمكن إرسال رسائل الاستعادة للمستخدمين الفعليين. لا حاجة لتغيير الجداول أو Edge Function أو السياسات.

## التحقق

نجح اختبار المتصفح tests/test_password_recovery.py بواجهات Auth محاكاة: الإدخال غير الصحيح، تقييد الإرسال، مستمع PASSWORD_RECOVERY الحقيقي في SDK، رفض التحديث دون جلسة استعادة، التأكيد غير المطابق، انتهاء الجلسة، نجاح التحديث ثم العودة لتفعيل الرمز، ومسح حقول كلمة المرور وعرض الهاتف.

نجح tests/test_pin_login.py لتسجيل الدخول بالرمز والتفعيل والصلاحيات والأجهزة الجديدة.

لم يُرسل بريد فعلي ولم تتغير كلمات مرور أو إعدادات Supabase الإنتاجية. بعد ضبط إعدادات النشر، اختبر رابطًا فعليًا من البريد حتى حفظ كلمة المرور وتفعيل الرمز.
